# 原生模型与零 Python 迁移

本执行路线以已发布的 `0.8.0-alpha.1` / `122bd2b` 为基线。本轮 **M0 门槛失败，已停止该里程碑**：固定本地对话未满足非思考预设，完整原生分发材料尚未闭合。0.9、0.10 和 1.0 beta 仍是后续交付目标；实际结果见[M0 原生验证证据](NATIVE_M0_EVIDENCE.md)。当前产品行为见[架构说明](ARCHITECTURE.md)，0.8 交付证据见[版本记录](releases/0.8.0-alpha.1.md)。

## 目标与保留边界

- 自有业务、桌面、测试和工程工具统一使用 Rust；官方本地运行链不需要 Python，允许使用原生推理库或进程。
- 用户解压程序后，在应用内确认下载模型或导入离线模型包；模型准备完成后可离线对话、听取、发声和检索记忆。
- 保留一号 OC、原生界面、人物/外形/场景包和 VTS。声音继续支持参考音频与对应文本；新后端不承诺复用旧 GPT-SoVITS 训练权重或产生完全相同的声音。
- 网页身体、完整 3D 编辑器和模型训练不并入本次迁移；远端 API 的内部实现不属于本地零 Python 验收范围。
- 旧数据、模型、凭据和参考音频独立保留。零 Python 不通过移除必迁移核心能力达成，也不要求卸载系统 Python。

2026-10-26 重新核对 Git 跟踪文件：125 个 `.py`，其中 `src/` 76、`tests/` 40、`tools/` 7、`models/` 1、根入口 1；另有 `requirements.txt`。与[逐文件清单](PYTHON_INVENTORY.tsv)一致。[能力矩阵](LEGACY_CAPABILITY_MATRIX.tsv)按行为而非文件数量记录迁移范围，不能把“已有 Rust 模块”解释为设备、模型或历史数据已通过验收。

矩阵的 `verified_scope` 引用 0.8 发布证据和编制时的源码核对；2026-10-29 的工程测试与原生探针结果另记于 M0 证据页，不回写为旧能力均已完成迁移。`partial` 表示仍有迁移/验收门槛；`design_retirement` 只表示有明确替代理由，不是文件删除授权。路径均相对于仓库根目录，分号表示多个入口，目录表示同一能力族。

## 分阶段交付

| 阶段 | 交付范围 | 必须满足的门槛 |
| --- | --- | --- |
| M0，不发布 | 固定模型与原生运行库；最小构建/推理闭环；协议、进程取消和资源校验基础 | Windows CPU 路径实际构建与推理；中文识别、默认发声和参考克隆；取消/退出；许可、摘要及文件清单有据可查 |
| 0.9.0-alpha.1 | 本地对话、识别、默认声音、专属音色、嵌入；模型管理和首次使用向导 | 新电脑在应用内完成准备，离线对话/抢话/记忆/重启恢复；缺少某个模型不会阻塞其他可用功能 |
| 0.10.0-alpha.1 | Windows 原生动作；旧记忆完整迁移；悬浮字幕、快捷键和必要旧体验 | 专用窗口、设备与旧数据副本验收；核心行为有替代与证据，未知结果不重试 |
| 1.0.0-beta.1 | Python 退役；Rust 工具收口；干净环境和分发验收 | 项目源码、构建、测试、程序包与官方本地运行链通过零 Python 门禁 |

**M0 是阻塞门槛。** 原生库文档/API 可用不等于固定 Windows 组合已经可构建、可推理。任一必需后端不满足门槛时，该里程碑保持未完成；不能改用 Python 或取消参考音色能力绕过。每个大版本发布后暂停，等待用户测试和明确恢复，再进入后续阶段。

## 固定后端路线

| 能力 | 实施目标 | 明确边界 |
| --- | --- | --- |
| 本地对话 | 托管独立 Ollama 原生实例，提供 Qwen3 4B 非思考预设 | 仅管理本应用启动的进程；用户已有服务保持独立 |
| 识别 | Sherpa-ONNX，多语种 Whisper small INT8 | 使用预转换模型，不在本机调用 Python 导出；M0 用公开测试音频，不接麦克风 |
| 默认声音 | Sherpa-ONNX，Kokoro v1.1 zh-en | 使用内建说话人，不需要先公开分发私人参考音频 |
| 专属音色 | Qwen3-TTS 0.6B Base ONNX，`wavekat-tts` 原生接口 | 参考音频与文本匹配；按现有分句整句合成，不假定后端可流式或及时中断原生算子 |
| 嵌入 | `ort` 与 Rust tokenizer，BGE-small-zh-v1.5 | 固定分词、pooling、归一化与模型空间；旧向量保留，重建显式执行 |

CPU 是基础路径，GPU 为另行验证的可选包。每个发布输入固定版本、文件大小、SHA256、许可及运行库要求；不以移动的 `latest` 或未核实摘要作为可用目录。模型包与本机安装不执行转换/训练脚本。

选型依据：[Sherpa Kokoro](https://k2-fsa.github.io/sherpa/onnx/tts/pretrained_models/kokoro.html)、[Qwen 原生接口](https://docs.rs/crate/wavekat-tts/0.0.5)、[Qwen 转换模型](https://huggingface.co/wavekat/Qwen3-TTS-0.6B-Base-ONNX/blob/main/README.md)、[ORT 本地运行库加载](https://docs.rs/ort/latest/ort/environment/index.html)。权重许可与程序许可分别核对；这些资料不是本机测试结果。

## 所有权与接口合同

桌面继续通过控制协议提交请求，服务拥有会话、模型进程、播放器、记忆与动作状态。推理和平台对象不进入 UI，服务组合根负责装配。原生后端按进程和 DLL 目录隔离，业务层保留现有安全 Rust 约束。

- 推理请求/响应携带请求 ID、会话代次和明确模型引用；控制消息经受管 stdio，音频使用会话临时文件引用，日志不混入协议 stdout。
- 打断立即撤销旧代次、停止播放并清空旧队列；无法协作取消的原生计算最多等待一秒后终止对应工作进程。取消请求不重放，迟到声音不得复活；只管理本应用持有的进程。
- 模型状态区分未准备、下载中、校验中、就绪、使用中和错误。查询/下载/离线导入/取消/移除都有可观察结果；完整校验成功前不替换当前可用版本。
- 声音预设明确区分内建说话人与参考音频，声明语言和所需模型。界面提供准备模型、选择/导入声音、试听和保存到人物的连续流程。
- 旧配置可读取并预览迁移，转换输出使用新文件；模型缺失只影响对应能力。人物和场景分享默认排除凭据、私人记忆与参考音频。

## 后续核心迁移合同

真实 Windows 动作新增独立 `StartNative`，不能把 `StartTemplate` 的合成端口直接替换为系统输入。原生会话使用真实全局许可和持久审计，绑定窗口、进程身份和几何代次；窗口失效、前台切换或几何变化时暂停核对。点击、按键、拖动、滚动、等待和无动作沿用受控协调与预算。视觉只提交建议，未知结果先查状态，部分执行不自动重试；仅释放适配器自己按下的输入。

旧实体存储主要是实体与来源记忆的关联，不是完整人物关系图。新版在同一 JSONL 中独立持久化导入候选和来源边，兼容读取 0.8 平铺记录，防止启动重建覆盖旧候选。本人、第三方与未知主体分别处理，更正/遗忘只撤销对应来源贡献；Chroma 通过原生服务打开工作副本后导出，原文件与原始快照保留。格式升级先备份，旧版回退使用原备份。

主动说话、冷却/免打扰、弹幕、语音/表情协调、配置受控生效、VTS 发现与诊断导出按能力整合。固定随机犯错/分心不继承，不把所有自然行为一并退役。现有覆盖和待办见[能力矩阵](LEGACY_CAPABILITY_MATRIX.tsv)，历史验证继续保留在[Rust 迁移记录](RUST_ONLY_MIGRATION.md)。

## 验证证据与停止条件

所有记录先注明范围，再记录结果；未执行项统一标记 `not_run`，不能由“编译通过”“API 存在”或 mock 结果推断真实推理成功。

| 证据项 | 必须记录 |
| --- | --- |
| 环境与源码 | 提交/工作区状态、Rust/目标三元组、Windows、CPU/GPU、构建参数与线程限制 |
| 原生输入 | 运行库和模型的精确版本、许可来源、文件大小与 SHA256、公开测试音频来源；不得放入个人凭据 |
| 执行结果 | 精确命令、退出码、日志路径、输出文件、中文识别/音频结构/向量空间核对 |
| 取消与退出 | 活动请求和代次、停止耗时、旧结果是否丢弃、进程是否回收、取消请求是否重放 |
| 性能 | 冷/热启动、识别耗时、首段发声、打断延迟、内存及 CPU/GPU；注明模型与重复方法 |
| 未测与阻塞 | `not_run` / `failed` / `blocked` 的具体原因，禁止用上游 benchmark 代替本机结果 |

M0 最小用例包括正常加载/推理、缺失运行库、损坏模型、大小/摘要不符、取消活动推理、终止退出和干净重启；正常与失败结果都需可观察。模型管理另验下载中断、导入失败和空间不足，不破坏现用模型。真实设备、窗口和旧数据副本验收由用户按流程触发；开发使用公开/合成文件、假设备和本地 mock，不操作正在使用的桌面。

最终门禁覆盖核心与桌面两套测试、严格 Clippy、fmt、架构边界，以及跟踪源码/依赖/启动命令/分发内容的零 Python 检查。Rust `xtask` 接管打包、检查与必要诊断，历史文档中的文字不按关键词误报。干净 Windows 环境需分别验证构建和便携运行，模型准备后断网完成主要流程；中文/空格路径、不同工作目录和精简 PATH 单独覆盖。

本文不删除旧实现，也不替代实际测试记录。退役仍依据当前精确文件清单与功能证据，保留 Git 历史和私人数据；不能按矩阵中的目录整棵删除混合内容。规则见[退役清单](LEGACY_RETIREMENT.md)，当前/历史文件归属见[项目目录](PROJECT_LAYOUT.md)。
