## 本轮可使用的新能力

### 1. 不连接外部服务的配置校验

```powershell
cargo run -p ai-ex-service --locked -- --config config/ai-ex.example.toml --validate-config
```

检查 TOML 与现有 AppConfig 约束，然后退出；不会初始化模型、读取控制令牌、打开记忆、启动后台连接或访问音频设备。它补齐开发/迁移时的离线检查；现有 `--check` 仍用于用户明确准备好的真实服务健康检查。配置读取与解析上限为 1 MiB，错误只报告位置，不回显原字段内容。

### 2. 旧记忆备份转为当前角色的 Rust 记忆

```powershell
cargo run -p ai-ex-migrate --locked -- --memory-backup `
  --input '备份路径/memory_backup.json.gz' `
  --output '新目录/imported-memory.jsonl' `
  --profile '明确选择的角色ID' --utc-offset-minutes 480
```

`--input`、`--output`、`--profile` 均必需。`480` 只是原备份按 UTC+8 本地时间写入时的示例；按原机器时间选择偏移。含 `Z` 或显式时区的时间不需要该选项；无时区的历史时间不猜测。目标必须是新文件，已有文件或并发创建的文件都拒绝覆盖。不直接覆盖正在使用的记忆库。

在备份副本上执行后，先核对角色 ID 与记录，再让**单独的测试配置**的 `[memory].path` 指向输出文件。Rust MemoryStore 可直接读取该 JSONL，并按角色召回；生产配置合并与桌面导入界面留待后续。合成端到端回归验证 gzip → CLI → JSONL → MemoryStore → 角色隔离 → 文本召回和重复导入拒绝覆盖。

支持旧 `memory_core.py::backup_memories` 的 schema 1.0 JSON/gzip 备份，检查 SHA256、数量、重复 ID、字段和时间。SHA256 按旧代码的 `json.dumps(memories, sort_keys=True, separators=(',', ':'))`：字段排序、紧凑分隔符、ASCII 转义（含 UTF-16 代理对），保留文件中数字的原始字面量，避免 `1e-05` 被改为 `1e-5`。独立固定测试备份使用 .NET SHA256 生成校验值；未执行原 Python 或读取用户备份，不能声称已验证每一份真实历史数据。

导入保留 UUID、正文和时间；`INTERACTION`/`SUMMARY` 转为 conversation，`EVENT` 转为 live_event。原 user_input/ai_response 存在时保留双方正文，否则保留完整 content。旧记录保持 Automatic 来源，不能当作用户确认事实。追加的语义记忆增量会保留非空向量到顶层 `embedding = {space, values}`，并把全部原 metadata 保留在 `legacy_metadata`；有向量时必须提供 `--embedding-space NAME`，不猜测模型身份。最多 8,192 维，拒绝非有限、全零或同一备份维度不一致的向量。空向量按无向量处理。原备份保持不变。工具仍不读取 Chroma SQLite/HNSW 库；独立实体集合与多模态模块没有包含在旧备份中，不能声称从这个备份恢复了它们。

压缩输入、解压正文和输出各上限 32 MiB；记录/数组元素上限 50,000；单条文本上限 128 KiB；嵌套上限 64。损坏/截断 gzip、重复 JSON 键、不支持的类型或未知时间拒绝导入。转换在独立阻塞工作线程执行，文件写完并同步后通过同目录硬链接发布；不支持硬链接的文件系统会报错并保留源数据，不能降级为覆盖写入。

### 3. 语音清洗与分句

Rust `SpeechCleanup` 接入当前 `clean_for_speech`，补齐原默认 Emoji、英文/中文括号舞台说明清理，保留中文标点并合并空白。提供原三项开关的 Rust API。嵌套括号完整清理；不闭合括号保留正文。内联代码沿用已有 Rust 规则不朗读，原 Python 曾保留代码内容，不能把这一差异写成完全相同。

流式分句继续使用原句号/叹号/问号/换行语义，改为只扫描追加后缀。UTF-8 分块、残句、清空和复用有对照回归；不改变消息身份、取消或播放时钟。

### 4. 可选语义召回与显式重建

默认继续使用本地文本检索。需要语义召回时，在单独测试配置中显式增加（模型名称和空间标识按实际部署填写）：

```toml
[memory.embedding]
base_url = "http://127.0.0.1:11434"
model = "your-installed-embedding-model"
space = "your-model-version-and-encoding-v1"
timeout_seconds = 30
```

配置本身不会下载模型。正常服务仅在检索和记录时使用 Ollama `/api/embed`，`truncate=false`，避免服务静默截断文本。`--validate-config` 仍完全离线。`space` 是模型版本、编码方式与预处理共同确定的稳定标识；相同维度不代表相同空间。旧 MiniLM 向量不能因为都是 384 维就与其他模型混查；导入可保留原向量，再显式重建。

```powershell
cargo run -p ai-ex-service --locked -- --config '测试配置.toml' --reindex-memory
```

维护命令只处理 `persona.profile_id` 选中的当前角色，逐条请求配置的 embedding 服务；任意一条失败则整批不发布，原 JSONL 与当前内存记录保持原样。它在模型聊天、音频、控制服务等初始化前退出；不自动在启动时扫描重建，不处理其他角色，不增加记录修订号。此命令实际运行会调用配置的模型，本轮验收只使用本地 HTTP mock。

每个独立 MemoryStore 首次修改取得 `<memory.path>.lock` 的操作系统独占写入锁，持有至最后一个 clone 关闭；正在写入的服务会使其他实例的重建/修改明确失败。首次取得写入权后重新读取磁盘，避免先打开的陈旧快照覆盖新内容。只读实例是打开时的快照，不是跨进程实时订阅。锁文件保留，不要在服务运行时手动删除它。

写入新对话或用户记忆时保存向量；更正会清除旧 metadata 并重新生成对应向量，模型失败则保留新文本、清除旧向量；普通写入的向量请求额外限制两秒，避免必须完成的记忆持久化让停止/退出等待漫长模型超时；显式重建仍按配置的请求超时执行；遗忘/清空同时移除原文和派生向量。没有配置向量模型时，更正也会移除失效向量。列表和控制协议传输 MemoryEntry 与有界的 knowledge 附加信息；完整向量与旧 metadata 不发送到界面，整页仍受 48 KiB 预算约束；导出 JSONL 保留全部持久字段。

查询只比较空间与维度均匹配的向量。余弦相似度达到 0.45 的候选参与语义召回，混合分数为 `0.8*cosine + 0.2*(命中查询词项数/查询词项数)`；未达到阈值的向量不贡献语义分，原词法命中仍可召回。用户主动记录/更正继续优先，组内按最近更新排序；自动记录按相关分数、更新时间、记录顺序排序。聊天上下文继续排除 live_event。未配置/暂时不可用的模型使用旧词法排序，健康状态说明 lexical fallback；不会用随机/哈希向量伪装语义检索。

词项与归一化向量在读取/写入时缓存；查询只构造一次词项集合，并用有界堆选择 top-k。当前是精确扫描，适合先验证真实角色记忆量的性能，没有宣称具备 Chroma/HNSW 的大规模性能。本轮继续接入实体候选与来源关系、多模态持久化和查询，见下节。旧核心 importance/近期上下文排除已提供第 6 节的显式可选策略；内嵌 MiniLM 推理与直接读取 Chroma 存储文件尚未实现，不能通过删除旧代码退役。
### 5. 实体来源与多模态记忆

实体和媒体数据统一保存在当前角色的同一条 JSONL 记录中，复用已有写入锁、修订号和原子更正/遗忘。没有另建独立数据库。实体由用户原话本地提取；旧备份只从显式 `metadata.user_input` 提取，不从助手回复、摘要或自动采集的媒体描述推断用户事实；用户在桌面明确录入或更正的媒体笔记仍可形成有来源的候选。规则覆盖姓名、喜欢/不喜欢/中立偏好和主要英文事实类别，另支持明确中文姓名、年龄、住址、职业与兴趣。它们是有来源的候选，置信度来自规则，不代表独立核实。第三方人物不能混入用户本人属性；旧第三方实体的独立建模与旧实体集合迁移仍须补齐，不能据此删除旧模块。

稳定属性键把不同说法关联到各自原记录，保留冲突候选与来源。当前显示值优先采用用户主动记录/更正，其次按更新顺序；不把不同说法静默合并为一个确定事实。更正重新提取，遗忘同时移除该记录贡献的关系。每个候选都可在桌面“实体”视图打开原记录；同一来源最多 24 个候选，序列化上限 8192 字节，提取输入上限 128 KiB。

媒体记录保留 Text/Audio/Visual/Multimodal 类型、文本描述、音频/视觉特征的嵌套 JSON、标签、metadata 与 0–1000 重要程度。多模态允许旧接口产生的缺省特征组合。桌面可以添加和更正描述、类型、标签、重要程度，并按类型、任一标签、最低重要程度筛选；匹配记录按重要程度、最近修改和记录顺序排列。每条媒体附加信息上限 8192 字节、最多 16 个各 64 字符标签。常规编辑保留没有修改的特征和 metadata；主动更改模态会明确提示清除不适用的特征。

`observation_media` 复用旧模块的本地重要性启发式：文本长度、音频 entities/视觉 objects 数和模态系数；它不运行声音或图像识别。`remember_media`、`media_stats`、`clear_media` 提供角色范围内保存、统计和按模态清除。查询和实体证据复用有界控制协议；长正文只缩短界面预览，持久文件保持完整。实体关系展示与媒体管理已进入桌面；原始图像/音频附件采集、真实媒体模型以及实体图对模型上下文的进一步编排仍不是本轮实现。旧访问计数可供第 6 节的显式维护使用；不会自动递增或触发定时淘汰。旧核心近期排除和重要性排序已有可选策略，真实媒体模型和完整旧模块仍未全部迁移。

旧多模态模块没有持久化导出协议。新增工具接收显式导出的 dataclass JSON 数组，不能把它称为既有备份或 Chroma 数据库：

```powershell
cargo run -p ai-ex-migrate --locked -- --multimodal-memory `
  --input '副本/multimodal-snapshot.json' `
  --output '新目录/imported-media.jsonl' --profile '明确选择的角色ID'
```

每项字段为 `memory_id`、`modality`、`text_content`、`audio_features`、`visual_features`、`timestamp`（epoch 秒）、`importance_score`（0–1）、`access_count`、`tags`、`metadata`。已有 UUID 保留；旧 `mm_<16hex>_<epochsecs>` 标识稳定映射为 UUIDv8，原 ID 与完整快照另保存在 `legacy_metadata`。输入最多 32 MiB / 50,000 条；描述最多 4096 字符；超限或无效记录整批拒绝，源文件不变。新文件发布沿用拒绝覆盖与原子写入。该模式不接受 `--utc-offset-minutes` 或 `--embedding-space`，不猜测不存在的向量。更正按既有规则清除旧 `legacy_metadata`，原快照输入仍保留在原文件。

### 6. 旧召回策略与显式媒体维护

上批合成回归已验证这两个独立入口；默认 `hybrid` 保持已有 Rust 召回。要在独立测试配置中使用旧核心默认 L2 候选与排序合同，可设置：

```toml
[memory]
recall_policy = "legacy"
exclude_recent_turns = 3
```

`exclude_recent_turns` 支持 0–20，0 表示不排除。队列只记录本次会话新保存的自动记忆 ID，最多 20 条；切换角色或重启后清空。新增确认笔记不会清空自动记忆排除队列。它按 ID 排除当前上下文，不按文本删除重复内容，也不改变文件中的访问计数。

Legacy 模式只比较相同显式向量空间、相同维度的原始向量：先选距离最近的 `min(limit*3, 50)` 个候选，再排除近期 ID、要求 `1 - squared_l2_distance >= 0.45`，取够返回数量后才按重要度加近期分排序。确认笔记/更正沿用当前上下文入口的优先保留规则。没有编码器或编码失败时使用词法候选，仍保持相同阶段顺序；不生成伪向量。此模式复现旧默认 L2 距离，不推断其他 Chroma 索引的距离定义。近期加分按实际代码 `max(0, 0.1 - age_hours/168)`，在 **16.8 小时**后为零；旧“一周”注释不代表这个算式。

媒体重要度的音频和图像系数均为 1.1，多模态为 1.2。显式维护使用旧算式 `importance * (1 + access_count*0.1) * exp(-full_age/30_days)`，并限制在 0.1–1；30 天是指数时间常数。重复执行会对当前分数再次按完整年龄衰减；不会在读取时增加访问计数。持久重要度沿用千分制，结果四舍五入。

```powershell
# 仅预览；不申请写入租约，不创建锁文件或归档
cargo run -p ai-ex-service --locked -- --config '测试配置.toml' --maintain-media --media-capacity 1000

# 确认应用；发生变化时必须指定新归档文件
cargo run -p ai-ex-service --locked -- --config '测试配置.toml' --maintain-media `
  --media-capacity 1000 --apply-media-maintenance --archive-memory '新目录/affected-originals.jsonl'
```

维护只处理当前角色的 Automatic 媒体记录；UserNote、UserCorrection 和其他角色受保护。先按访问计数/年龄调整分数，再预览清理候选：年龄超过 30 天且调整分数低于 0.3，或可维护记录数超过容量的 90% 且分数低于 0.2。阈值在千分制舍入前判断。这不是严格容量上限，也没有后台自动淘汰。

应用前先在写入租约下重新读取记录，将**所有受影响的原记录**写入新 JSONL 并同步，再整体替换测试库；原正文、嵌套特征、元数据、向量和来源保留在归档。已有归档拒绝覆盖；替换失败保留归档与原库。归档只包含受影响原记录；完整回滚还需要事先保留整个测试库副本。维护在模型、控制服务和设备初始化前退出。

### 8. Rust 模板匹配与受控游戏回放

新增独立的 `--template-game MANIFEST.json`，完整清单与合成回放流程见 [模板游戏说明](TEMPLATE_GAME.md)。入口在服务配置读取前分流，无需 `--config`；从明确指定的 PNG/JPEG 文件读取帧，沿用旧游戏 profile 与其 `templates/` 目录。模板宽高各 20–200 像素，灰度归一化匹配有显式工作预算；图像局部命中经过捕获原点、缩放和物理桌面范围映射为归一化指针坐标。

每步通过同一个 AutomationCoordinator 执行捕获、移动、点击及各自 permit/审计；支持单次点击、重复点击和只悬停。单次点击仅在点击成功且完成审计持久化后完成；移动失败、急停或审计缺失均停止，不自动重试可能已经执行的动作。帧数、指针动作数和输入内存分别受限，报告保留部分 receipts 与明确失败阶段，不含 RGBA。报告始终输出 stdout，指定文件时拒绝覆盖，文件持久化失败仍保留已输出的执行证据。

50 ms 默认间隔按离线时间戳筛选图片、时间和 geometry，不消费被跳过的帧，不提供实时 20 Hz 承诺。连续三次追踪未命中回退到用户固定搜索区域，十次未命中只报告 Lost，后续仍可重获。当前由 DryRunAutomationPort 消费合成/指定图片和记录动作；真实 Windows 捕获、键鼠 adapter 与 GUI 控制集成仍属必迁移核心，旧实现继续保留。

本次已确认自动化库 46 项测试通过，其中新增 12 项受控工作流集成回归；服务 CLI 与微基准结果以该说明中的后续验收记录为准，尚不声称真实游戏、设备或帧率验收完成。

受控反射 SDK 随后增加 `ReflexSession`、可克隆的 `ReflexControl` 与跨 await 的永久代次租约。派发前在授权审计返回后再次复核；暂停再恢复、两步之间的代次变化均清除旧追踪，保留总 misses 和消耗。已确认且完成审计成功的单次点击不会因迟到的暂停重复执行。直接取消已开始的 step future 会使 controller 失败，派发后保守计入一个可能已执行动作，禁止重试；不伪造完成回执。需要完整报告时用 stop 加等待自然返回。

该 SDK 检查点通过 80 项自动化测试、全部 feature 的 8 组模板 CLI 回归，以及 workspace 全部 target/feature 严格 Clippy 和格式检查；上一离线回放检查点的整 workspace 回归为 400 通过、2 忽略。当前服务尚无与真实聊天共同运行的 reflex owner；30 秒静默恢复、VLM/队列仲裁、GUI 接线和真实 Windows 动作仍须继续迁移，不将 SDK 验收写成已启用的游戏功能。
## 模块设计与取舍

| 职责 | 实现边界与选择 |
| --- | --- |
| 身份/消息/错误 | domain/protocol；保留版本化类型、AppError 分类，无设备/GUI 依赖 |
| 会话与取消 | core 单一 actor；沿用有界意图/语音队列、背压与代次取消，不引入线程池并行争抢话轮 |
| 模型/语音/外形 | 既有 Ollama/KoboldCpp/DeepSeek、TTS、ASR、audio/capture、VTS/OBS adapter；通过端口隔离外部服务，推理实现可独立部署 |
| 持久数据 | memory 按角色隔离 JSONL；migrate 提供离线格式转换和显式只读 Chroma v2 导出，不自动确认事实 |
| 桌面 | desktop 只消费控制协议和投影；业务状态不复制到 GUI，保持已有角色/外形/场景流程 |
| 平台动作 | safety/automation/audit 保留 permit、急停、目标范围和审计；真实 Windows 捕获/键鼠 adapter 尚未迁移，默认保持关闭 |
| 开发工具 | Cargo 管理编译/测试/基准，现有 Windows 启动/打包 PowerShell 保留；不新增 Python 工具。是否把全部 PowerShell 逻辑也移入 Rust xtask 属于后续工具整合 |

优先复用现有协议与模块，不重建另一套运行时。实体规则使用本机已有缓存的 regex 1.13.1，规则只编译一次；领域层增加已有 serde_json 依赖以保留嵌套媒体结构。两份锁文件仅增加必需依赖边，不升级其他包。迁移器复用已缓存 flate2/ring，新增缓存中的 time 作明确时区解析，不自行编写日期运算或密码学。memory 只作为 migrate 的测试依赖验证输出可用；生产迁移工具仍只使用 domain/config 与格式库。没有新增 unsafe，也没有依靠语言本身宣称高性能或完全安全。

| GUI/人物/场景 | 当前原生桌面、离线预览、收藏、素材册与场景已取代旧主线 GUI | 验收完整首次设置/重启故事；迁移旧悬浮字幕、全局快捷键等独有核心体验 |
| 视觉/游戏/自动化 | 当前只读视觉、permit/审计、插件协议；新增 Rust 灰度模板匹配与同 coordinator 的受控游戏 dry-run，支持追踪、坐标映射、预算和部分失败报告，见[回放说明](TEMPLATE_GAME.md) | 补真实 Windows 捕获/键鼠 adapter 与桌面集成，保留旧核心合同并做受控实机验收；离线图片回放不代表真实游戏已迁移完成 |
| 自然行为/优化/热重载旁支 | 技术基线明确它们未进入当前 Rust 主链，旧报告的固定优化数字不继承；仅测试引用不足以证明废弃 | 按真实调用与当前体验需求整合，删除前列出不再需要的合同；不机械重写所有 *_optimized 变体 |
| Python 诊断/测试/依赖 | 工具索引明确为旧实现工具；当前 CI 已使用 Rust | 逐项用 Rust CLI/原生回归替代；最后移除 main.py/requirements.txt，建立零 Python 门禁 |

这些状态是静态调用和当前产品入口的证据，不证明用户从未使用某个旧脚本。完全 Rust 化不能通过先删目录、再把缺失能力都标为“未来规划”实现。

接下来按完整功能切片继续：1）补齐高级记忆剩余原生数据库桥接与召回策略合同（向量/实体/多模态已提供可用切片）；2）受控桌面捕获与动作适配器，复用 permit/审计和急停；3）在已有 Rust 模板匹配与离线游戏回放上接入受控真实捕获/键鼠及桌面入口；4）桌面集成旧独有核心体验，整体退役旧入口、脚本、测试及依赖。领域/端口与平台实现分离，先合成/mock 对照再实机；同类边缘审计延期，正常回归跟随功能。所有必迁移核心能力仍在目标范围，不再需要就保留与否重复询问用户。最终验收需要 `git ls-files '*.py'` 为零、Python 依赖/命令为零、当前核心与桌面构建/测试/lint通过，并逐项说明旧功能保留或有依据退役、数据迁移和设备未测范围。
