# 记忆工作台

本文说明当前记忆工作台，包括实体候选、主体与来源核对、媒体描述、标签，以及旧平铺记录的格式升级。桌面与服务需一起更新；升级时保留原配置和记忆备份。整体入口见[验收流程](MANUAL_TEST_PLAN.md)。

记忆页让你直接管理当前角色留下的记录。换外形仍使用同一个角色身份；切换不同档案 ID 后，列表、查找和修改都进入另一份角色范围。

上图是原有基础界面的示例笔记离屏渲染，不展示本轮新增的实体或媒体视图。真实窗口交互仍需按验收流程体验。

## 从界面开始

在“设置与诊断 → 连接设置”勾选“启用长期记忆”，保存后重启对应服务；关闭该选项不会删除已有记录。连接并同步角色后，在主窗口顶部打开“记忆”。没有连接时可以先写笔记草稿；角色正在回复或声音尚未播完时，先等待结束，或点击“打断回复”。

| 想做什么 | 操作 | 结果 |
| --- | --- | --- |
| 看它留下了什么 | 点击“查找 / 刷新”，输入关键词或选择分类；使用上一页、下一页 | 只显示当前角色的记录，较新的更改排在前面 |
| 明确记下一件事 | 展开“记下一件事”，在“希望你记住……”填写准确内容，点击“记住这件事” | 新建一条由你确认的笔记，标为“你明确记下的事” |
| 改正错误 | 在记录上点击“更正”，写清完整的正确事实，再点击“保存更正” | 替换这一条记录，标为“你更正过的内容” |
| 删除一条经历 | 点击“遗忘”，核对预览后“确认遗忘” | 只删除所选记录；“保留记忆”可取消 |
| 查看或复制原文 | 展开“查看原文”，或点击“复制内容” | 可查看当时的输入和回复；超长记录的列表预览和复制内容为片段 |
| 备份当前角色 | 展开页面底部的“备份当前角色的记忆”，点击“准备备份记忆”，阅读提示后点击“确认生成备份” | 在服务记忆文件所在目录生成本角色备份，成功后显示位置；不会清空聊天 |

当前显式记笔记、更正、遗忘及部分维护操作会重写共享记忆文件，可能丢失旧版附加字段或重建后的知识内容，包括其他角色的记录。处理旧数据前，请先停止相关服务并保存完整原始文件副本；不要把角色备份当作原始文件副本。

如果已保存的实体与当前提取结果不同，开发分支会阻止可能覆盖它们的整库改写、角色备份、导出和升级；查看仍可用，只含新版记录的记忆文件也仍可直接追加。请先保存完整原始副本，暂缓修改并核对数据。升级预览中的 `changed_saved_entity_records` 表示受影响的记录数。此保护尚不能检测所有未识别字段或来源状态的变化，不能保证其他转换完全无损。

每次新建、更正或遗忘成功后，服务清空当前短期上下文，桌面收到成功应答后清空聊天显示。下一轮重新检索剩余记忆；聊天输入草稿保留。更正不是在原文后面追加反驳：它把这一条改为新的确认笔记，并移除该条旧回复。

新建编辑器默认折叠，浏览记录时不占据主要空间。点击记录的“更正”会自动展开并定位编辑器；已有草稿也会保持展开。

较长记录可分别点击“分段查看原文”或“分段查看回复”，每次点击“读取下一段”才会读取下一段；画面只保留当前一段。切换角色、记录列表或断开连接后，需重新选择。记录已变更时请刷新后重新查看。分段不会自动填入更正草稿；遗忘仍操作整条记录。

角色备份包含当前角色的私人记忆及相关线索，请妥善保管。它会筛选并重新序列化记录，可能丢失未识别字段或改变重建后的内容，不能替代完整的原始文件备份。迁移或修改旧数据前，请先停止所有使用该记忆库的服务，并另存整个原始记忆文件及相关资料的副本；该副本可能包含其他角色的私人数据。备份时聊天和角色切换可能需要等待；结果未知时文件可能已经生成，可以手动查询原编号，或在了解可能已有文件后确认生成新备份。不会自动重发原请求。编号只在本次桌面会话保留；服务重启或关闭应用后无法保证再次查询，请检查原保存目录。核对后可点击“已核对，不再提醒”，记录和未知状态仍会保留到本次会话结束。关闭本应用管理的服务可能中断尚未确认的备份。

开发分支可展开“备份完整原始记忆文件”，先准备并核对目标路径，再确认生成。它复制同一文件中所有角色及未识别字段，可能包含私人资料，请妥善保管；复制时其他程序若直接修改文件，无法保证副本为完整快照。目标已存在时不会覆盖。结果未知时请保存界面显示的操作编号和路径并查询或核对，不会自动重试；切换角色仍可查看记录，服务实例变化后不能查询原操作，关闭应用会丢失本次记录。生成中退出可能留下临时文件。

开发分支的“记忆 → 检查已有记忆备份”可选择新版 JSONL 或旧版 JSON / JSON.GZ，输入服务所在电脑上的备份绝对路径，点击“检查备份”后查看统计结果。Windows 上可直接粘贴“复制为路径”的结果；也可点击“准备拖入备份”后拖入一个文件，确认填入的路径后再点击检查。等待拖入时不能检查旧路径，也可先点击“取消拖入”。新版检查核对格式结构及记录中的角色标签，不能证明文件来源或完整性；空文件或角色标签不符会被拒绝。旧版检查核对 memories 的哈希与数量，其余字段未受哈希保护；不核验角色归属，无法证明文件来源或能否导入。如果提示含本地时间或向量，迁移时分别需要指定时区或向量空间；未分类记录还需要进一步核对。检查不恢复或合并记忆，迁移需要另行操作。路径不会自动读取；如果填写 UNC 或其他网络路径，检查会访问相应网络位置。等待中的检查会在发送前核对，已开始发送的检查可能继续。真实私人旧数据尚未验收。

检查旧版备份后，可点击“准备生成候选”，填写服务所在电脑上的现有输出目录，并按提示指定固定 UTC 偏移（分钟）和旧向量实际所属的空间，再审阅角色、源文件、目标文件和参数，点击确认。准备结果有效期为 5 分钟，源文件发生变化会被拒绝；检查不证明文件来源或角色归属。固定偏移不能表达跨夏令时的变化，向量空间未知时应先核对，不要猜测。候选是包含私人记忆的独立 JSONL，不覆盖现有文件，也不会自动合并或启用。生成可能失败或结果未知；请保留页面显示的操作编号和目标路径、查询状态并核对文件，不要自动重试。每次服务最多保留 32 项候选操作记录；记录已满时新操作不会开始，请先核对未完成操作，再重启服务。服务重启后无法查询原操作，关闭应用也会丢失本次记录；意外中断可能留下临时文件。真实旧数据副本仍待验收。

开发分支可在同一页面展开“合并两份备份为独立候选”。填写两份新版 JSONL 备份的绝对路径，也可使用上方已填写或拖入的备份路径；点击“检查两份备份”，核对角色、记录数、来源和向量空间，再填写服务所在电脑上已有的输出目录并审阅两份来源及目标文件，确认后才会写入。请使用已关闭且不再变化的备份副本；生成时会核对与预览相同的字节，但不能保证其他程序并发改写时的读取是原子快照。空文件没有角色标签，需要自行确认归属；检查只报告首个冲突，同名向量空间会被拒绝，名称不同也不证明语义兼容。候选不会覆盖文件或自动启用；原始行中的未知字段虽被保留，现用存储后续重写仍可能丢失它们，不能当作已无损导入。结果未知时保留操作编号和目标文件并查询，不自动重试；服务重启后无法查询原操作。网络路径会访问相应位置，真实旧数据副本尚未验收。

记忆页的笔记草稿按角色分别暂存，切换回来可以继续编辑；这些草稿只保留在本次桌面会话中。成功保存的笔记才会持久化。离开当前会话时，有未保存内容会提示。

## 来源与召回

| 界面标记 | 含义 |
| --- | --- |
| 自动记录 · 未经确认 | 完成的对话或外部事件留下的记录，可能包含错误理解或模型生成内容 |
| 你明确记下的事 | 你在记忆页主动保存的笔记 |
| 你更正过的内容 | 你改写并保存后的记录 |

“确认”表示你明确保存或更正过，不表示系统独立核验了事实。自动记录不会因为存进文件就变成已确认事实。

当前角色的确认笔记优先进入对话召回，不要求当前问题与笔记具有相同关键词；仍受 `memory_recall_limit` 限制，多条确认笔记按更新时间等顺序选择。自动记录按相关性召回，原始直播事件不进入默认对话召回。记忆页的关键词查找是内容过滤，与模型上下文的召回排序是两种用途。

## 实体线索与来源核对

切换到“实体线索”，查找姓名、偏好或事实；点击“查看关联原记录”进入来源记录，再使用原有的“更正”或“遗忘”。普通记录上的候选线索按钮也能进入同一来源视图。

例如，分别保存“我喜欢咖啡”和“我不喜欢咖啡”，会得到同一个咖啡偏好线索及两条来源。来源概览出现不同值时，界面提示“存在不同说法，请核对关联原记录”。“当前候选”优先取你明确记下或更正的记录，其次按更新顺序选择；它不会消除其他来源，也不表示已经判断哪句话是真实情况。

候选来自本地规则对用户正文的提取，覆盖姓名、偏好、年龄、位置、职业等英文主要类别与常见中文明确自述。模型回复不用于提取用户身份；旧导入记录没有明确 `user_input` 时，也不会从混合内容猜测用户事实。自动媒体描述也不用于推断用户身份。提取会排除可识别的否定身份或事实、假设、第三方姓名和问句；“不喜欢”等负向偏好仍可形成候选。它不是通用语言理解或独立事实核验。

更正后，线索依据新的正文重新生成；遗忘后，该条来源不再参与线索聚合。其他记录仍可能保留旧说法。要核对所有关联记录，请进入来源页翻页；概览只保留有限条来源。

旧 Chroma 实体导入后作为独立候选保留，来源标为“导入”，不被启动时的规则提取覆盖。本人、第三方和未知主体分别展示；同名候选不会跨主体自动合并。旧资料没有明确主体时保持未知，不因存在来源或较高置信度而成为本人已确认事实。

关联来源区分有效、缺失、已更正、已遗忘和未解析。更正或遗忘只撤销该条来源的贡献，其他有效来源继续保留；全部声明来源已撤销后，不再显示当前值，旧候选和来源状态仍用于核对。缺失或未解析关联不会在重启时自行激活。无法定位的旧来源只显示原始标识，不能直接用它执行更正或遗忘；完整原始元数据保留在导入数据及原始快照中。来源概览只用有效来源判断当前说法差异。

## 媒体与标签

“媒体与标签”视图支持正文关键词、媒体类型、多个标签和最低重要程度筛选。多个标签用逗号分隔，匹配其中任意一个即可；标签匹配忽略首尾空白和大小写。结果先按重要程度，再按更新时间排列。未附媒体信息的普通记录按文本、重要程度 0 处理。

展开“记下一件事”后，可选择文本、声音描述、画面描述或声画描述，填写标签、重要程度及相应描述，再保存正文。这里保存的是描述和结构化特征，不负责录音、拍照、解析原始文件或生成媒体理解结果。

更正已有媒体记录时，只改正文会保留原有嵌套 `audio_features`、`visual_features` 和媒体 `metadata`；修改声音或画面描述只更新对应的 `description` 字段。主动改变类型会移除不再适用的声音或画面特征，界面会在保存前提示。未改动的其他嵌套数据继续保留。旧声画记录允许音频或视觉特征缺省；未修改描述和类型时，编辑器保留这种缺省状态。

每条媒体信息最多 16 个非空标签，每个最多 64 个字符；媒体对象整体最多 8192 字节。界面重要程度显示百分比，控制协议和存储使用 0–1000。已有特征较大时，应留意保存错误提示，不能把“描述框还能输入”当作整个对象一定能保存。

要复现完整流程，可在独立测试角色中保存一条带“旅行”标签的画面描述，按标签和类型找到它，改正文后再次核对描述，重启服务并选择同一角色查看，然后遗忘该条记录。旧多模态显式快照的离线导入见[维护工具与脚本](../tools/README.md#显式多模态快照导入)。

## 遗忘的实际范围

操作针对一条记录。导入候选会保留已撤销的来源状态和原始导入材料供核对；遗忘来源不删除已有备份、原始快照或其他来源。若相同信息也出现在其他对话、笔记或角色设定中，需要分别更正或删除；系统不会自动发现并清除所有重复含义。清空当前上下文有助于避免刚删除的内容继续从当前聊天历史送给模型，但不能据此声称已完成概念级全局遗忘。

私人记忆不随角色包、外形包或场景包分享。移出角色收藏也不删除该角色记忆。记忆以本地 JSONL 保存；被召回的内容会随请求发送给选用的模型，云模型请求中的这部分内容会离开本机。

重新启动后，持久记录仍可由相同档案 ID 使用；**重启后的完整聊天记录显示和全部短期历史恢复尚未实现**。记忆召回不等于恢复原来的整段对话。

## 遇到提示时

| 情况 | 下一步 |
| --- | --- |
| 服务未启用长期记忆 | 在“设置与诊断 → 连接设置”勾选“启用长期记忆”，保存后重启对应服务；源码配置也可设置 `[memory] enabled = true` |
| 正在回复或播放 | 等待结束或打断后再管理；保存期间暂缓新聊天和角色切换 |
| 记录已变更或不存在 | 刷新后核对当前记录，再重新进入更正或遗忘；不会用旧版本覆盖新内容 |
| 操作结果尚未确认 | 保留草稿，先“查找 / 刷新”核对是否已写入；核对前不能再次修改，不会自动重发 |
| 较长记录，仅显示片段 | 列表的“查看片段 / 复制片段”只处理预览；可按需分段查看原文或回复。更正从空白输入开始，请重新写完整事实 |

更正和新建最多接受 4096 个字符，查找词最多 512 个字符。列表分页并限制单次响应大小，较长记录可逐段读取，原始存储不会因为浏览而截断。遗忘仍针对整条记录，确认前请核对选中的内容。

## 状态与存储边界

请求携带当前 `profile_id`；更正、遗忘还携带记录 ID 和预期记录 `revision`。服务拒绝跨角色请求和过期记录版本。这里的记录版本与角色设定版本分别维护。

写入由运行时协调，存储先写入并同步同目录临时文件，再替换原文件；成功后才更新内存状态。已开始的持久修改会完成后再收束，关闭请求不代表修改一定没有发生。通信中断时应按“结果尚未确认”处理。

同一个 JSONL 同时只允许一个写入方：第二个独立服务或重建进程会被操作系统写入锁拒绝，需先停止原写入服务；只读实例保留打开时的快照。实体线索可追溯到本角色的来源记录，并保留明确的主体与来源状态；跨角色共享、关系推导、派生摘要清理和外部事实核验仍未实现。

## 旧文件升级与回退

同一 JSONL 使用版本 2 记录：普通记忆仍保留顶层 `id`、`user_text`、`embedding` 等字段，增加 `schema_version: 2` 和 `record_type: "memory"`；导入候选与来源关联分别使用 `entity_candidate`、`entity_source` 行。角色范围、原始候选和来源状态一同持久化，重启不会重新猜测导入关联。

0.8 的平铺行可直接只读打开，不会因查看列表改写文件。第一次获准的持久修改会先把原文件的**原始字节**保存到旁边的 `<原文件名>.v1-backup-<UUID>.jsonl`，再写新格式。备份保留原换行、空行和向量；过期版本等被拒绝的修改不触发格式备份。退回旧版前先退出服务，保留新版文件，再使用这份原始备份作为旧版数据，不能把新格式文件直接交给旧版，也不能依赖 Git 恢复私人记忆。

需要先检查转换结果时，关闭正在写入的服务，对**自行准备的副本**运行：

```powershell
cargo run -p ai-ex-migrate -- --upgrade-memory --input 'C:\exports\old-memory-copy.jsonl' --preview
cargo run -p ai-ex-migrate -- --upgrade-memory --input 'C:\exports\old-memory-copy.jsonl' --output 'C:\exports\memory-v2.jsonl'
```

预览只输出格式、记忆、候选及来源数量，不写文件。输出必须是新文件；原副本不变，身份与向量空间标识保持原值。该命令不猜测旧 Chroma 的 SQLite/HNSW 格式。Chroma 的“关闭旧程序 → 新工作副本 → 固定原生服务导出 → 离线导入”流程见 [Chroma 迁移说明](CHROMA_BRIDGE.md)。未知旧格式不会自动修复原库。

模型或预处理变化时，新的向量属于新的空间，旧向量不能混查。先备份并关闭写入服务，确认目标人物与模型已准备，再显式重建当前人物索引：

```powershell
ai-ex-service.exe --config 'C:\exports\native-bootstrap.toml' --native-config 'C:\exports\native-v1.toml' --reindex-memory
```

重建保留文本与来源，失败不提交半套向量；它不会自动迁移其他人物的数据。版本化来源、更正／遗忘、重启、角色导出和原字节备份已通过合成数据测试，固定原生 Chroma 的真实合成 SQLite/HNSW 副本流程也已通过。真实私人旧库验收仍为 **`not_run`**，采用导入结果前需要用户用独立配置和旧库副本核对。
