# 整体验收流程

适用范围：**0.10.0-alpha.1 Windows 便携版**。完整解压后，先完成下面的无设备体验，再按需要测试声音、麦克风与专用窗口。桌面、服务和平台助手需一起更新；没有执行的项目记为“未测”，不用先跑命令行检查。

## 0.10：先检查设置与字幕

可以继续沿用已准备的 0.9 CPU 组件和模型；升级前关闭程序，将新版解压到新目录，保留原目录及私人数据备份。不要用分发模板覆盖旧个人配置。

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| R1 | 连接后进入“设置与诊断”，读取运行设置 | 主动说话、悬浮字幕和全局快捷键默认关闭；重启后快捷键显示未注册 |
| R2 | 开启字幕、保存应用，再显式试听或发起有声音的对话 | 独立字幕只跟随确认播放；打断、停止试听和断线后旧字幕消失，不显示尚未播放的整段回复 |
| R3 | 修改字幕位置、字号和鼠标穿透，关闭后重开 | 本地样式偏好保留；开启字幕本身不启动声音或麦克风 |
| R4 | 确认其他程序不占用快捷键后，启用并应用 | 显示实际注册状态；Ctrl+Alt+F6 打断，F7 急停，F10 切换字幕；冲突明确报错 |
| R5 | 有意测试主动输出时，设短冷却并启用，保持空闲 | 仅空闲时生成短输出，没有伪造的用户气泡，也不把系统意图写入你的记忆 |
| R6 | 主动输出中发送文字，或开启免打扰；再检查静音时段 | 用户对话优先；关闭、免打扰、静音时段与急停撤销主动输出，不在稍后补播 |
| R7 | 导出诊断，检查导出文件 | 新文件包含版本和允许导出的运行状态，没有原始日志、对话、密钥、窗口标题、完整路径或参考录音文本 |

VTS 用户可在已有有效连接中发现当前模型的热键，核对名称及 ID；发现操作不触发热键。未连接时应显示该能力不可用，不影响聊天与人物预览。

开发分支另可在运行设置点击“核对 VTS 表情映射”，检查生效热键 ID 和匹配状态；切换人物后重新核对。未载入人物的已设置项应显示无法核对，断线或错误时不沿用上一次结果。此核对不会触发表情；真实 VTS 连接尚待用户验收。

## 0.10：由你打开专用画布

完整步骤和许可配置见[Windows 原生操作](NATIVE_DESKTOP.md)。先双击随包的 `AIex-Test-Window.cmd`，仅选择该画布，保持声音和主动输出关闭。这里会由你主动测试真实输入，开发期间没有代替你执行。

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| W1 | 权限关闭时扫描并尝试准备所选窗口 | 能看到显式窗口列表；没有许可不能捕获或输入 |
| W2 | 按说明配置精确路径许可并重启，重新扫描绑定 | 准备状态显示真实进程身份、位置与 DPI，不立即发送输入 |
| W3 | 保存手动点击、按键、文字、拖动、滚动、等待和无动作，逐项切回画布，F9 核对恢复、F11 单步 | 每次只执行保存的一步，画布显示对应事件；没有视觉模型也能测试 |
| W4 | 移动画布、改变大小、移至不同 DPI 屏幕或负坐标区域 | 旧位置操作被拒绝，先显示待核对几何，再由你恢复，不误点其他窗口 |
| W5 | 切到其他窗口、关闭画布、重启同名画布 | 不沿用旧窗口/进程身份；前台变化暂停，重启需要重新绑定 |
| W6 | 操作中 F8 暂停、F7 急停，或发起聊天 | 截图和动作旧代次撤销；只释放助手自己按下的输入，聊天后不自动恢复 |
| W7 | 将截图/动作预算设小并连续显式执行，再停止 | 达到预算后拒绝；停止、未知结果、部分失败均不自动重试 |
| W8 | 有视觉模型时改存一个清晰目标，切回画布 F11 | 每次只采纳一个受限动作；超时或停止后的迟到建议不能执行 |

## 0.10：旧记忆只在副本上验收

先关闭旧程序，保留旧配置、数据库快照和参考音频。按[Chroma 桥接](CHROMA_BRIDGE.md)使用固定原生程序打开**新建的工作副本**，输出新快照，再导入新的 JSONL；源目录保持不变。普通 0.8 JSONL 可先用 `--upgrade-memory --preview` 查看，升级输出必须是新文件；服务首次改写旧格式前会保留原字节备份。

在验收角色中核对：本人/第三方/未知主体、同名候选、多个来源、缺失关联、冲突值。更正或遗忘一个来源后，其他有效来源仍保留；重启后导入候选和来源状态不被重新提取覆盖。不同角色不能互相看到记录。模型空间改变时显式重建，旧向量不能混查；回退旧版本时使用原始备份。

真实私人旧库、混合 DPI、真实设备与听感均需在反馈中记录“通过/失败/未测”。合成库或无窗口自动测试通过，不能代替这些验收。

## 本地伙伴：先只用文字

完整解压便携包，双击 **`AIex.exe`**，按向导准备所需能力；首次下载、校验与模型冷加载需要等待。可以先点“先体验外形”看一号 OC，再回到首页进入本地准备。

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| N1 | 首页点“准备本地伙伴”，再点“创建本地设置” | 模型和声音向导打开；麦克风、播放均关闭，原有连接配置保持原样 |
| N2 | 在“1 · 本地对话”查看运行组件和 Qwen3 4B 的大小、许可与来源，分别“下载准备”→“确认下载” | 有下载和校验状态；完整通过后显示“已就绪”，不会自动打开音频设备 |
| N3 | 有离线包时，改填对应组件的目录或 ZIP **绝对路径**，点“从本地导入” | 固定版本和全部文件通过校验后可用；模型先导入时可保留已校验文件，补齐运行组件后无需重下 |
| N4 | 文字体验先跳过语音，进入“4 · 试听与保存”，点“进入聊天”；发送“你好，请用一句话介绍自己” | 显示流式中文回复；第一次加载可能较慢，仍能操作界面 |
| N5 | 让它写长一点，点“打断回复”，再发新问题 | 旧轮次不再补出文字或声音，新问题可正常继续 |
| N6 | 在“记忆”给验收角色保存一条明确笔记，退出并重新打开程序，再核对同一角色 | 已保存笔记和本地设置仍在；不要求完整聊天显示或全部短期历史恢复 |

“同时准备本地记忆检索”可单独准备 BGE；未准备时不能据此判定笔记保存失败。文件“已就绪”表示校验及依赖满足，不等于模型已经加载，也不代表回复质量或声音相似度已经通过验收。

## 你准备好后：播放与专属声音

下面的操作会由你主动开启声音。没有准备播放设备时可以跳过，不影响前面的文字体验。

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| S1 | 到“本地模型与声音”的“3 · 选择声音”，准备 Kokoro，选默认中文声音 | 可看到模型状态和所选声音，不自动播放 |
| S2 | 在“4 · 试听与保存”点“启用对话声音”，保存后**再点**“播放试听” | 只在点击试听后发声；字幕、人物口型跟随实际播放，试听不会新增聊天轮次 |
| S3 | 播放中点“停止试听”，再试听一次；也可在试听中发送新聊天 | 旧试听停止，不会在新回复后补播；重新试听仍可使用 |
| S4 | 在“用参考音频制作专属声音”中准备 Qwen3-TTS，填写声音名称、WAV 绝对路径和录音实际原文，点“导入并保存专属音色” | 导入完成后出现专属音色；原文件不变，新副本存入私人声音目录 |
| S5 | 选新声音，试听，再点“保存声音到当前人物”；进入聊天并重开程序核对 | 当前角色继续使用已绑定声音；换外形不会改变声音绑定，分享人物/场景不带参考录音或原文 |

参考 WAV 需为清晰语音，最长 30 秒；服务接受 PCM 或 Float WAV，导入时转换为单声道 PCM16。听感、音色相似程度、长句稳定性和首次出声等待由你实际判断，记录“可接受 / 有问题 / 未测”即可。

## 可选：麦克风与离线重启

1. 先准备 Whisper 识别模型。在“2 · 语音开关”勾选“启用麦克风，进行语音输入”，点击“应用语音开关”，再点“进入聊天”重新进入，使开关生效。保存开关本身不开始采集；自有服务会在需要时重新打开。
2. 说一句中文，核对识别文字及回复。回复播放中再说话，观察是否及时打断、是否出现旧音频补播。暂不测试时保持麦克风关闭。
3. 所需组件全部就绪后，退出程序、断网，再打开并测试文字、已启用的声音和已保存笔记。缺少某项模型时，其他已准备能力和人物设置仍应可用。

向导只自动重开自己托管的本地服务；复用已有外部服务时，按该服务的管理方式重启后再测麦克风。

下载中可点“取消准备”；摘要错误、目录不可写或缺少运行组件应有具体错误，不应标为就绪。出现“结果待核对”时先点“刷新状态”，核对当前设置和组件；程序不会自动重发原操作。重开程序会重新核验缓存，大模型校验可能需要等待；退出会取消未完成的准备和校验。

便携原生数据位于 `data`：`native-bootstrap.toml` 管服务连接，`native-v1.toml` 管模型/设备/私人声音绑定，`native/packages`、`native/voices`、`native/jobs` 分别存组件、参考声音和临时作业；记忆是 `native-memory.jsonl`。设置更新保留原版本备份。不要用旧版直接写新版数据；回退时使用更新前保留的数据副本。

反馈只需写 **版本、N/S 步骤、实际现象、是否启用了设备**。日志在 `data/logs/service.log`；分享日志前去掉个人对话或凭据。GPU 包、未安装 Python 的干净 Windows 以及真实设备尚需独立验收，不作为上述自动测试已经通过的结论。

## 保留的外部连接与外形体验（可选）

下列流程从 0.8 沿用，本版继续保留外部模型、OC、人物包、场景、记忆和合成回放；不需要为了使用本地向导把它们全部执行一遍。历史 0.8 便携包也适用这一部分。

### 先用起来：无需命令行

完整解压 `AIex-Windows-x64-0.9.0-alpha.1.zip`，双击 `AIex.exe`。不要在压缩包里直接运行，也不要只取出一个 EXE。欢迎页显示版本号。

**前五分钟先看外形。** 点击“先体验外形”，展开“外形与自定义图片”，在“内置立绘”中切换“01 · 一号人物”和“02 · 初始伙伴”。选择一号人物，试试“半身近景”和“全身立绘”，再向下展开“OC 素材册”查看六种素材。最后缩小窗口并滚动，确认人物设置、素材册与底部“开始对话”仍能找到。这个过程无需模型或密钥。

| 顺序 | 你需要做什么 | 应该看到什么 |
| --- | --- | --- |
| 1 | 点击“先体验外形” | 首次默认显示内置 OC“一号人物”，无需导入素材、账号、模型或其他软件；已有外形偏好继续保留 |
| 2 | 切换两个人物；一号人物试半身、全身和素材册，初始伙伴试情绪；调整舞台点缀 | 构图按比例显示，初始伙伴保留原有情绪；素材册只查看静态图，不改变舞台状态或人物选择，点缀不改变服装 |
| 3 | 在预览底部点击“开始对话” | 未配置模型时打开连接设置；无需关闭并重新打开程序 |
| 4 | 选择你已有的模型服务，填写信息，保留自动启动服务并保存 | 主界面连接成功；模型可用时可以回答 |
| 5 | 输入中文，Enter 换行，Ctrl+Enter 或“发送”提交；再让它写长一点并点击“打断回复” | 输入法确认不会误发；旧回答可停止，新问题仍能继续回答 |
| 6 | 新建自己的角色，修改称呼、语气，预览后确认应用；再换外形 | 当前角色按确认结果切换，换外形不改变角色身份 |
| 7 | 保存一号人物的全身场景，再载入并确认；设置为启动组合 | 已应用角色、人物选择与全身构图一起恢复；未确认时不会改变当前组合 |
| 8 | 关闭并重新打开程序，再进入对话 | 本机收藏与已设置的启动组合能恢复；云端密钥可能需要重新填写 |

聊天页以对白卡片、固定输入区和人物舞台为主；角色、场景、记忆、设置从顶部切换。把窗口缩小到最小尺寸，输入框与发送按钮仍应可用，历史内容可滚动。在“设置与诊断”进入“连接设置”或“首页”，有未保存草稿时应先提示。旧 v1 内置场景恢复初始伙伴；单独切换人物、构图或查看素材不会修改人格和记忆。

一号人物目前使用局部眨眼、说话帧与半身近景的细微呼吸；“表情参考”是一张完整六格图，另四张动作也只供静态查看，不以它们自动切换对话情绪作为通过条件。

若看到未送达提示，检查恢复到输入框的文字；输入框已有新草稿时，从“查看保留的消息”恢复或复制。连接超时的文字会标为“结果待核对”，不会自动放回输入框；先检查服务是否已经回答，再决定恢复，避免重复发送。

第 1、2 步完全离线。第 4 步起需要你自己的模型服务：云端密钥，或已经启动并装有模型的 Ollama / KoboldCpp。程序包不包含模型。

本版先测试外形、文字、角色和记忆；语音与麦克风默认关闭，准备好资源后再测试。不需要先安装 VTube Studio。

反馈只需写：**第几步、点击了什么、实际看到什么、期望什么**。启动错误窗口可复制错误信息；需要日志时查看程序目录下的 `data/logs/service.log`，分享前去掉个人对话或凭据。

便携模式使用 `data/ai-ex.local.toml`，默认端口 17878；下面源码深度检查使用另一份配置和端口。两种流程不必一起执行。角色收藏仍有本机共享设置，请给测试角色加“验收”前缀。

## 已有连接后的约五分钟体验

这组用于回归记忆工作台，前提是连接成功，并在连接设置中勾选“启用长期记忆”、保存后重启服务。使用自己的测试角色，先不打开麦克风或语音；详细说明见[记忆工作台](MEMORY_WORKSPACE.md)。

| 顺序 | 操作 | 应该看到什么 |
| --- | --- | --- |
| 1 | 在聊天输入框留下未发送草稿，切到“记忆”，展开“记下一件事”并保存“验收笔记：我喜欢杏色” | 出现“你明确记下的事”；聊天显示重新开始，原输入草稿保留 |
| 2 | 点击该记录的“更正”，完整改为“验收笔记：我喜欢浅蓝色”，保存 | 该条变为“你更正过的内容”，不再显示旧句；查找可找到新内容 |
| 3 | 点击“遗忘”，先“保留记忆”取消一次，再确认遗忘 | 取消时记录保留；确认后只删除这一条，其他记录保持可见 |
| 4 | 再记下一条测试笔记，切换到不同档案 ID，再切回来 | 不同角色的列表分开；返回原角色还能看到它的笔记 |
| 5 | 在外形预览选择初始伙伴，切换思考、表达、陪伴与情绪，再勾选“减少动态效果” | 保留原有状态与情绪表现；减少动态后停止呼吸、眨眼与说话帧；惊讶不持续无声张嘴 |

记忆成功先以列表与应答为准，不用模型是否答对来单独判断。相同信息如果存在于其他记录或角色设定，需要分别处理；这里测试的是单条更正和遗忘。重开程序后可再核对原角色的已保存笔记，但**完整聊天显示与全部短期历史恢复尚未实现**。

若遇到“操作结果尚未确认”，先刷新核对，不能直接再点一次保存；草稿应保留。把窗口缩至最小尺寸，长笔记可滚动，遗忘确认中的操作按钮应可达。真实模型是否稳定遵循确认偏好、播放与打断的实际延迟，仍需你后续整机验收。

## 可选：合成模板回放

先完成本页前面的模型连接并确认服务可用，再按[模板回放说明](TEMPLATE_GAME.md#准备一个独立回放目录)在单独目录准备合成图片、profile 和 manifest。这组检查读取清单中的图片，所有捕获、移动与点击都在 dry-run 主机中记录，不会读取真实屏幕或发送真实键鼠。

建议选 `click_repeat` 或 `hover`，用较长的测试回放留出操作时间，例如每帧间隔 1000 ms、64 帧、`max_frames=64`、`max_actions=128`，帧时间戳严格递增；可以让多个帧条目引用同一张合成图片。`click_once` 命中即结束，不适合体验后续的暂停与恢复。manifest 省略 `strategy`；回放本身无需 VLM，聊天联动继续使用已经配置好的对话模型。

| 编号 | 操作 | 应该看到什么 |
| --- | --- | --- |
| R1 | 在“设置与诊断”的“合成模板回放”中填写 manifest 绝对路径，点击“开始回放” | 服务确认载入后显示运行阶段，帧数、动作数和结果随合成输入更新；文件内的图片和 profile 仍相对 manifest 目录解析 |
| R2 | 点击“暂停回放”，等当前步骤收束，再点“刷新回放状态” | 显示手动暂停，之后不再开始新捕获或点击；已经派发的步骤允许完成并计入消耗 |
| R3 | 确认恢复条件为空闲，点击“恢复回放” | 同一会话继续处理后续合成帧，已消耗的帧与动作预算不清零 |
| R4 | 回放运行时发送一条简短测试聊天，再回到设置页查看 | 暂停原因为聊天；已接纳和排队的话轮、转写或语音仍忙时不能恢复，全部空闲且自最后一次聊天静默满默认 30 秒后才自动恢复 |
| R5 | 再发送一次聊天，在聊天暂停期间点击“保持暂停”，等模型完成并超过静默期限 | 保持手动暂停，不再自动恢复；只有恢复条件为空闲时，才可用“恢复回放”显式继续 |
| R6 | 在运行或暂停时点击“停止回放”，再刷新状态 | 最终显示已结束/已停止，已开始步骤收束后计数稳定；该会话不能恢复，继续需要显式开始新会话 |
| R7 | 若出现“状态待核对”或操作结果不确定的提示，点击“刷新回放状态” | 清单草稿保留，不自动重新开始或重发变更；相同快照仍可能保持待核对，不要求刷新后立即解锁；连接有效且会话已知时仍可请求停止 |

以上回放操作不会启用真实自动化。可选战略观察会调用明确配置的视觉模型，准备方式和边界另见[战略观察循环](TEMPLATE_GAME.md#可选战略观察循环)，不纳入本组默认体验。没有准备合成清单或模型连接时，将 R1–R7 记录为“未测”。反馈时附版本、测试编号、界面显示的阶段/暂停原因/计数和触发时间。

## 6. 可选：真实声音与插话

此部分由你准备好设备后操作。先保持麦克风关闭，单独验证播放。关闭测试服务，在测试 TOML 中补全已有 `[tts]` 段（不要重复添加同名段）：

```toml
[tts]
enabled = true
base_url = "http://127.0.0.1:9880"
ref_audio_path = "D:/你的音色目录/reference.wav"
prompt_text = "填写参考音频中真实说出的文字"
text_lang = "zh"
prompt_lang = "zh"
```

启动已配置模型与音色的 GPT-SoVITS 服务，再以测试配置重开桌面。参考音频必须能被合成服务访问；上面的路径是占位示例，需要替换。

| 编号 | 操作 | 通过条件 |
| --- | --- | --- |
| E1 | 请求短回答并等待播完 | 能听见语音；字幕按当前句显示；静音时嘴部回落 |
| E2 | 请求多句回答，观察模型生成结束后的朗读 | 仍在播放的字幕、情绪和口型继续跟随该句；不因生成完成提前消失 |
| E3 | 分别在合成等待、播放中、文字生成完但声音未完时打断 | 剩余旧语音停止；立即提问可播放新回答，无旧声音插回 |
| E4 | 重复同一句回答两次，连续做几轮对话/打断 | 两句均能正常播放；旧进度不会重新激活已经取消的句子 |
| E5 | 停掉测试 TTS 服务后提问，再恢复并继续 | 故障可诊断，程序不崩溃；恢复后新一轮可播放 |

记录从点击打断到实际停止的时间，以及是否有设备残留缓冲声音。250 毫秒是单次适配器等待上限，不是设备实测延迟指标。

播放测试通过后，配置实际 Whisper 兼容转写接口，在原有 `[duplex]` 段设置 `enabled = true`，补充以下子段并重启：

```toml
[duplex.asr]
endpoint = "http://127.0.0.1:8000/v1/audio/transcriptions"
model = "whisper-1"
language = "zh"
```

使用耳机测试说话、停顿、背景噪声及朗读中插话，记录转写准确度、误触发与抢话效果；先通过点击打断，再区分麦克风/VAD、转写和运行时问题。采集关闭后不应继续接受麦克风输入；修改开关需重启服务。

## 7. 可选：VTS、OBS、直播与更长会话

- VTS：按实际应用配置接口和表情热键，验证连接、动作及断线后的文字对话。恢复应用后再发起对话，观察诊断。原生外形仍可独立使用。
- OBS：配置 WebSocket 凭据环境变量和实际字幕输入源，验证字幕、断线与重连。当前生成动作不等于播放同步，不把词级口型作为通过条件。
- 直播：[Bilibili 连接说明](BILIBILI_CONNECTOR.md)。先使用建议模式验证事件，再由你决定是否测试自动回应。
- 连续使用：保留一个固定角色和场景运行多轮，记录响应时间、资源占用趋势、重复回复、身份连续性和退出结果。偶发模型表现问题与可复现程序故障分别记录。
