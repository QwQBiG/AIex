# 人格与记忆

本文适用于 0.7.1-alpha.1，说明角色身份、分类记忆与确认笔记的行为。界面使用见[记忆工作台](MEMORY_WORKSPACE.md)。

人格位于 `[persona]`，与 `[model]` 分离。更换 DeepSeek、KoboldCpp 或 Ollama 不会改变角色名、语气、禁忌和直播模式；服务会把人格配置编译成会话系统提示词。

```toml
[persona]
profile_id = "default"
revision = 1
name = "AIex"
system_prompt = "你是一个友好的数字伙伴。"
tone = "warm, concise, and curious"
taboos = ["不要泄露密钥", "不要绕过急停"]
live_mode = "controlled"
```

`profile_id` 与 `revision` 组成角色档案版本；服务启动时加载初始版本，控制协议可在无活动回合时热切换。切换失败不会替换当前人格。

## 角色身份与经历隔离

`profile_id` 是记忆归属的稳定标识，按原字符串精确匹配。编辑名称、语气或版本时保留该 ID，短期对话和长期记忆继续使用；切换不同 ID 时，运行时先停止旧角色排队的声音，再切换记忆范围并清空短期上下文。切回原 ID 后可以召回它的持久记忆，但不会重新注入切换前的整段短期对话。

桌面“角色与外形”页的“角色设定与收藏”可编辑档案 ID 并应用，也支持[角色包](CHARACTER_PACKS.md)的导入草稿与导出。运行中的切换不改写服务初始配置；可以在 `[persona]` 中设置默认角色，或将桌面当前角色与外形设为[启动组合](SCENE_PACKS.md)，在重新打开时按同一档案 ID 恢复。[角色收藏](CHARACTER_LIBRARY.md)支持选择已有身份或复制出独立身份；移出收藏不会删除对应的记忆。

每条新记忆写入 `profile_id`。召回、计数、分类导出和分类删除都限制在当前角色内；同一服务中共享存储的直播写入方也跟随当前角色，切换会等待已开始的读写完成。禁用记忆时仍可切换角色，但不会持久保存经历。外形选择不改变这个 ID。

旧文件中没有 `profile_id` 的记录只属于 `default`，不会自动归给新角色，也不会在读取时改写原文件。以前使用自定义档案 ID 的用户如需查看这批旧记录，可暂时使用 `default`；显式认领/迁移界面尚未实现。导出的记录保留身份标记，读取导出文件时需选择对应的角色范围。

隔离是同一存储文件内的逻辑分区，不是加密或独立文件权限。当前还没有按交互对象细分或跨角色显式共享。单条管理成功后会清空当前短期上下文与聊天显示，但不清除其他记录、角色设定或外部模型中可能存在的相同信息。

自动验证使用本地模拟模型和真实服务进程，检查角色往返切换时实际模型请求中的历史/召回隔离，以及相同角色重启后的持久记录。真实模型的长期人格表现和扬声器上的切换延迟仍由[整体验收流程](MANUAL_TEST_PLAN.md)验证；重启后完整聊天显示和全部短期历史恢复尚未实现。

## 查看、更正和单条遗忘

主窗口新增“记忆”页，支持关键词与分类查找、分页、查看来源、明确记下笔记、更正和确认遗忘。在“设置与诊断 → 连接设置”勾选“启用长期记忆”，或在源码配置设置 `[memory] enabled = true`；保存后重启对应服务。关闭开关不会删除原记录。活动回合或播放期间界面提示等待或先打断，未连接时可以先写草稿。

新建笔记标为 `user_note`，更正后标为 `user_correction`；完成的对话与事件记录使用 `automatic`，界面明确显示“未经确认”。更正会替换该条原输入、清除该条旧回复，并转为 `persona` 分类。用户保存过不等于经过独立事实核验。

更正和遗忘要求角色 ID、记录 ID 与预期记录版本全部匹配；旧版本请求被拒绝后需刷新重新核对。记录版本独立于人格 `revision`。新建、更正和遗忘持久化成功后，下一轮从新的上下文与剩余记忆开始；聊天输入草稿保留。通信结果不明时不自动重试，先刷新核对是否已经写入。

超长记录会标为片段，更正时从空白输入重新写下完整事实，避免把传输片段当作全文覆盖保存。遗忘仍删除整条所选记录；相同信息在其他记录或人格提示中需要单独处理，这不是概念级全局遗忘。

## 本地记忆分类

`ai-ex-memory` 使用本地 JSONL 保存记录。启用召回后，相关片段会随对话上下文发送到所选模型；使用云模型时，这部分请求会离开本机。每条新记录包含 `kind` 字段：

| 分类 | 用途 | 默认行为 |
| --- | --- | --- |
| `conversation` | 普通对话上下文 | 运行时自动写入和检索 |
| `viewer` | 观众偏好、称呼和关系 | 由直播事件编排层显式写入 |
| `persona` | 长期设定与笔记 | 记忆页的新建和更正写入此类，来源另行标记 |
| `live_event` | 礼物、关注、直播场次等事件 | 由事件总线适配器显式写入 |

旧版本没有 `kind` 的 JSONL 记录会自动视为 `conversation`，无需迁移文件。

运行时上下文不会把所有分类无边界地塞给模型：默认上下文只检索 `conversation`、`persona` 和 `viewer`，排除 `live_event` 原始记录；每次仍受 `memory_recall_limit` 上限约束。这样可以保留观众关系，又避免直播事件日志无限扩大上下文。需要审计或回放时，再通过分类 API 单独检索 `live_event`。`MemoryPort::recall_for_context` 是核心的可替换边界，未来可接向量检索或远程记忆而不修改 Runtime。

对话召回优先选择当前角色的确认笔记，即使新问题没有复用相同关键词；多条笔记按更新时间等顺序排列，仍共同占用 `memory_recall_limit`，不会无限注入上下文。自动记录继续按相关性召回。旧记录缺少来源与记录版本时，按 `automatic` 和版本 `1` 读取，不会自动升级成确认事实。

分类记忆由 `MemoryStore` 提供以下管理能力：

- `recall_kind`：只检索指定分类，避免观众信息污染角色设定。
- `count`：查看单类或全部记录数量。
- `export_kind`：导出指定分类到新的独立 JSONL，写入后同步落盘；目标已存在时拒绝覆盖，包括原始记忆文件。再次导出请使用新的文件名。
- `clear_kind`：清除指定分类，保留其他分类。先向同目录的唯一临时文件写入并同步，再直接替换原文件；替换失败时保留原文件和内存记录，可解除文件占用后重试。不会覆盖已有的 `.jsonl.tmp` 文件。

上述行为已覆盖 Windows 文件占用、重复导出、清空最后一类和重新打开文件的回归测试。当前存储仍以单个服务进程为写入方；多个独立进程同时修改同一个 JSONL、突然断电和进程强杀恢复尚未验收。

平台无关事件总线提供 `project_memory` 投影：聊天/关注/订阅进入 `viewer`，礼物/付费支持同时产生观众关系和 `live_event` 记录，游戏观察和系统通知进入 `live_event`；审核事件和定时器默认不写入记忆。服务层可以把投影交给 `MemoryStore::remember_projection`，模型 Provider 不需要了解事件或存储格式。所有自动响应仍继续受权限、冷却和急停策略约束。

自动行为继续由 `SafetyGate` 统一拦截：聊天/语音可以自动，外部发言、礼物动作和游戏输入必须经过权限、审计、冷却和急停。
